## 2. QQ 消息接入

- 使用 NapCat，只读取当前 QQ 账号中置顶的群聊消息；实时接收、首次历史读取和断线补漏均使用同一范围。非置顶群不分析、不保存，不处理私人对话和已确认机器人账号的消息。
- 连接及重连时重新核对置顶状态，运行中同步置顶变化；无法可靠取得置顶名单时暂停消息读取并报告原因，不回退到所有群。取消置顶后停止读取该群的新消息，不自动删除已有事项或证据。
- 上段探针验证（2026-10-11，历史记录；正式宿主结果见第 1 节）：项目只读桥已加载真实 QQ，52 个已加入群中仅 9 个置顶群参与历史读取；两轮 18/18 到达日期边界、去重 341 条、受控重连 1/1，退出码 0。模拟实时过滤和置顶变化通过，本次没有真实实时群事件；不等于正式应用、非预期断网补漏或长期稳定性完成。
- QQ 接入只读，不向 QQ 群或私聊发送消息。学校群通知、测试提醒和任务提醒均不通过 QQ 发送；第一版通过两张桌面卡片展示待办和待确认，不发送 Windows 系统通知。
- 用户已确认 QQ 在本机登录；接入时检查 NapCat 对应环境和连接是否就绪，普通 QQ 登录状态不作为 OneBot 连接成功的证明。
- NapCat 同时提供 Shell 和 Framework 两种接入模式。Shell 是无界面接管路线；同一账号不能同时登录普通桌面 QQ 和 Shell，不能把两个进程同时作为同一账号的接收端。Framework 在桌面 QQ 进程中加载 NapCat，目标是保留桌面聊天并提供消息接口；本机已加载并验证只读接口，用户确认聊天列表和窗口正常显示。实时群事件限定范围通过（观察到 1 条），长期稳定性尚未验证。
- 本机已准备并校验官方 NapCat Framework v4.18.37，在当前 QQ `9.9.36-53644` 中实际启动并自动登录；WebUI 6099 和 OneBot 3001 均已监听，只读探针取得 52 个群和一群一页的 7 条历史消息。原 QQ 文件未修改；不把这一页历史作为七天补漏通过，也未发送消息。
- QQ 重开提供便捷桌面入口，不要求用户到项目目录寻找脚本：桌面“QQ”快捷方式使用 Framework 启动入口，保留 QQ 名称和图标，原快捷方式先备份；QQ 已运行时再次点击打开已有窗口，不自动退出或重启 QQ。消息提纯继续按现有规则自动重连；这不等于登录 Windows 后自启动已实现。
- 本地规则提出疑似机器人账号，用户确认后才排除；按账号记录，支持撤销。
- 首次启动尝试回溯最近 7 天的群消息；断线重连后自动尝试补漏。
- 主界面显示 QQ 消息连接状态和失败原因，连接断开时自动尝试恢复；取消持续断开超过 5 分钟的系统通知。
- 历史读取范围以 QQ 实际返回为准。补全失败时显示对应群和失败原因。
- 按群及消息 ID 去重，历史补漏不重复创建事项或重复触发相同提醒。
- 消息、证据、同步位置、卡片内容和本地通知列表按 QQ 账号隔离，去重包含账号标识；切换账号须用户明确确认，原账号数据保留。两张卡片只显示当前账号工作区，操作核对账号及事项版本，不能查询或完成错账号事项。
- 登录 Windows 后自动启动软件，在系统托盘后台运行；自动启动默认开启，设置中提供开关，用户可自行关闭或重新开启。

## 3. 本地识别与相关性

当前实现状态（2026-10-12）：AccountCandidateRouter 首轮本地候选自动路由已实现，账号独立的 `routing.sqlite3` 保存回执与普通通知，messages/tasks/routing 三库 schema 1 不变。Task + 正式 Time 自动建事项，普通清楚行动不要求发布者预先列入可信名单；可靠关联 Change 自动更新同一事项，不能自动接受的冲突和 Pending 保存待确认，Notice 保存本地普通通知列表，Ignored 仅保存回执。ProcessAndRoutePending 按原发送时间，在单条消息事务中提取原消息并路由；RoutePending 遇到更早未提取消息先等待。KnownTasks 完全由当前持久化事项投影替换调用者旧快照，只有当前群 TrustedSenders 授权高影响变更，原发送者不自动升级为可信发布者。尚未路由的关联 Pending/Change 在原课程确认仍匹配时重核对；普通原 Pending/Task/Notice 不升级。每条消息的提取、处理版本、事项、证据、操作和回执一次事务提交，通知元数据使用最终处理版本；已路由消息的更高 ProcessingVersion 不自动重放，M6 重新分析协调仍待完成。路由前重新核对当前课程确认，确认被撤销或变更时，旧 Task/Notice/Change 降级为待确认并保留旧候选供核对；暂时排除课程、发送者或取消置顶时保留未路由消息及已有事项。普通通知列表表示学校群中的普通通知，与已取消的 Windows 系统通知无关；普通通知转任务仍待完成。

- 只提取学校通知和作业，过滤日常闲聊。
- 结合行动要求、日期上下文、适用对象、群与课程关联等规则判断；短消息不能仅因字数少被丢弃。
- 自动提出课程及群关联候选，由用户确认、修改或排除，复用已确认关联，不要求先手填课程名单。
- 用户确认所提供 QQ 截图中红框标出的群均为学校相关群。学校群名称通常正规，群名可辅助提出关联候选；也存在非正式名称，不能仅凭群名风格排除。截图中截断的名称不补全，取得真实群列表后再核对。
- 保存课程/群关联修改后，重新检查受影响群仍保留的本地消息及已有事项证据，展示实际检查范围；找回原来被自动排除但现在可靠相关的事项，不承诺恢复已清理的消息。重查保留人工修正、确认/拒绝/忽略、合并拆分、完成/取消/归档及历史台账；冲突或旧任务变得不相关时提出待确认建议，不自动删除任务，新发现事项刷新对应卡片，不发批次汇总系统通知。
- 自动识别面向全体及明确与本人课程相关的事项；相关性不确定时进入待确认。
- 必须完成的作业、考试、提交等事项可形成任务；自愿活动、竞赛等作为通知，用户可自行加入任务。
- 支持手动新增任务，用于补录口头布置或未被自动识别出的事项；用户填写标题、课程和截止日期/时刻，任务来源标注为“手动添加”，并使用与自动提取任务相同的优先级、提醒和完成规则。
- 根据消息原始发送时间解释“明天”“下周一”等相对日期，并区分提交期限、活动时间与其他日期。
- 需要行动但无法确定截止日期的事项进入待确认，补齐并确认后进入正式任务卡片；只有日期时保留日期精度，不补写具体截止时刻。

## 4. 图片辅助

- 图片文字识别采用 RapidOCR 本地方案；本轮已用真实学校通知截图完成离线识别实测，正文文字、位置和置信度通过，日期角色仍需人工确认。
- 文字消息完整时，图片和 OCR 文字作为卡片的辅助信息。
- 文字消息缺少时间等关键信息时进入待确认，展示原图及 OCR 文字供用户手动补齐。
- 图片中的日期须经用户确认后才能用于提醒；OCR 失败时仍保留原图。
- 用户明确说明：真实截图中的“10月12日之前交齐”是班长要求同学按期交齐材料。软件提取的是用户需要完成的事项及截止日期建议；群消息和 OCR 正文是待分析的学校通知内容，不是用户对编码助手或软件的操作指令。软件不代交材料，也不回复 QQ 消息。
- 日期范围“9月26日—10月16日”属于表格填写范围，不能直接建立提醒；图片日期只保存为 `SuggestedTime`，正式任务时间须经用户查看原图后确认。
- demo 删除“我已查看原图并确认所填写的日期和时刻”的独立勾选框。用户填写或修改日期后，点击“确认并加入任务”或“保存修改”即完成确认；“填入建议”仅填入表单，提交前不确立正式时间。

## 5. 任务合并与变更

当前实现状态（2026-10-12）：账号独立的 `tasks.sqlite3` 已保存正式事项、待确认、追加证据、操作前后历史、版本及撤销凭据；完成后 1 小时、忽略后 24 小时的边界和重启恢复通过自动回归。可靠关联 Cancel/Postpone/NewRequirement/Remind 首轮自动应用，取消不受手动时间保护阻挡；受保护时间冲突及已归档/已取消事项的新要求保存待确认。已完成事项的可靠 NewRequirement 恢复待办并保留完成历史；自动新要求保留稳定标题，新正文记录在原消息、证据和操作历史。自动 Remind 只追加证据，不覆盖正式时间或恢复事项。共享接受逻辑中，Remind 未传 confirmedTime 时不使用候选 Time；用户显式确认新时间仍可修改。LEFT JOIN 核对全部已关联证据的原消息时间，任一来源缺失时间、晚到旧消息或同秒顺序冲突均转待确认；当前按原发送时间保守协调，尚未完整支持 real_seq 或跨群原转发顺序。用户接受冲突建议仍通过既有生命周期事务更新原事项。图片 `SuggestedTime` 不自动变为正式时间。本段只实现时间字段保护；完整手动字段编辑、普通通知转任务、M6 重新分析协调、合并拆分及正式卡片变化显示仍在后续阶段；变更系统通知及系统提醒联调已取消。

- 明确属于同一任务的内容、时间和补充要求合并，保留各条原始消息。
- 催交更新原任务；明确的延期、取消和要求修改按字段保护规则更新对应任务并记录变化；仍在待办中的任务同步更新卡片变化标记。
- 用户手动填写、纠正或确认图片建议的正式字段受保护，重复消息不覆盖。可信新延期与手动截止冲突时，保留旧正式值及当前提醒，显示待确认差异，用户接受后才替换和重算；未手动覆盖字段仍可自动更新。明确取消不受手动时间保护阻挡，确认课程/群关系不等于手动覆盖该群所有任务字段。
- 能明确关联到原任务的延期、取消或提交要求变更，更新任务并在主界面保留变更记录；仍在待办中的任务刷新卡片及变化标记。无法明确关联的变更仍进入待确认，不发送变更系统通知。
- 老师明确取消且能关联到原任务时，移出待办和桌面卡片，保留“已取消”记录及原始消息；不记为用户已完成。
- 不能明确关联到某个任务的补充或变更消息进入待确认。
- 最近 7 天是消息回溯和分析窗口，不是任务保留期限；长期任务跨周保留。
- 逾期不自动完成或归档；任务由用户手动勾选完成，也可手动归档。
- 任务详情提供“归档”，归档后移出待办和桌面卡片，保留“已归档”记录及证据，不记为已完成。任务页提供已归档筛选，详情可手动恢复待办；恢复使用最新有效信息并刷新卡片。
- 已归档事项不因重启、重查或普通补充自动恢复；收到明确新行动要求时形成关联待确认建议，用户接受后再恢复待办。
- 完成后移入已完成记录，停止提醒，保留原始消息供查看。
- 已完成任务收到能明确关联的新行动要求时，自动恢复为待办，在卡片及主界面标出新要求；保留之前的完成记录及新旧消息证据。普通补充说明不自动恢复；关联或有效截止信息无法确定时，仍按既有规则进入待确认。
- 点击“完成”后立即移入已完成记录，并提供 1 小时内的撤销入口；撤销后恢复为未完成状态并刷新桌面卡片。
- 完成后的即时提示和 1 小时内的已完成记录均使用“撤销”作为撤销按钮文字。
- 忽略待确认事项后提供 1 天内的“撤销”入口；撤销后恢复到待确认列表。
- 新任务、通知和待确认事项显示未读数量及小红点。
- 打开并查看新任务、通知或待确认事项后自动标记为已读。
- 点击主窗口关闭按钮时默认隐藏到系统托盘并继续运行；设置中允许改为直接退出软件。

## 6. 优先级与桌面提示

历史实现（2026-10-12，旧通知方案）：持久化提醒第一段已接入 AccountWorkspace 与当时的任务详情，保存默认/小时/日历/关闭选择、计划、NeedsReview 和投递台账；最终服务 46/46、工作区提醒 24/24。ReminderPlanner、SQLite plans/ledger 和可控 sink 验证结果作为历史产物保留，`reminders.sqlite3` schema 1 不变。旧版页面显示“系统提醒尚未开启”，当时 Windows 实际投递及后台循环尚未接入。用户现取消该渠道，这些产物不再作为后续 Windows 接入任务，也不作为正式桌面卡片完成的证据。

- 本地自动计算 P0～P3，用户可以手动调整；结合截止时间与明确的事项后果。
- 基础分级：P0 为已逾期或今天截止；P1 为未来 3 天内；P2 为未来 7 天内；P3 为更晚。依次匹配，避免区间重叠。
- 明确影响成绩、考试资格或说明逾期不收时，可提高一级；不根据孤立关键词推断后果。
- 所有实时、手动、历史、补漏和课程修复产生的任务统一刷新桌面卡片；按当前截止/开始信息排序并高亮临期或逾期事项，不发送新发现或批次汇总系统通知。
- 第一版取消全部 Windows 系统通知弹窗和声音，不提供声音、系统提醒、自定义提醒时间或安静时段入口；不进行通知权限恢复、通知点击或声音播放验收。
- 提交任务展示截止，考试/需参加活动展示开始；开始时间已过显示对应标签，不误记为作业逾期或自动完成。只有日期时保留日期精度，当天仍有效。
- 有效延期按字段保护规则接受后，卡片使用新正式时间、重新排序并更新高亮；与手动正式字段冲突且尚未接受时，保留旧正式值并展示待确认差异。
- 重启、睡眠恢复及重新连接后读取当前工作区并刷新卡片，不补发时间节点或恢复汇总系统通知。
- 逾期后保持卡片高亮和待处理状态，直到用户手动完成或归档；待确认通过常驻卡片提示，全部处理后隐藏。
- 取消、完成、归档及延期与工作区快照和卡片操作核对当前状态及版本；失效事项及时移出或更新，原消息、处理记录和历史台账保留。

## 7. 桌面卡片与通知列表

- 桌面组件统一展示“提醒事项”和“待确认”两张卡片，可拖动、调整大小，固定在桌面显示。
- 两张桌面卡片采用左右排列。
- 桌面卡片仅在桌面显示，切回桌面时可见，不覆盖其他软件窗口。
- 两张桌面卡片首次显示时由软件根据屏幕空间自动摆放；用户拖动或调整大小后记住新的位置和尺寸。
- 提醒事项卡片按优先级和截止时间排序，显示任务标题、课程或来源群、优先级、截止时间及查看详情、完成入口。
- 临近截止和逾期任务高亮；任务保留到手动完成或归档，明确取消的任务按取消规则移出，没有任务时显示“暂无待办”。

## 8. 实现技术路线

- 真实 Windows 应用采用 **C# WPF + WebView2**。
- 现有 HTML/CSS/JS 原型作为 WebView2 中的界面基础继续复用；WPF 负责窗口生命周期、系统托盘、登录后启动、本地持久化、NapCat 通信、工作区刷新及桌面卡片窗口层级。
- 桌面卡片的“仅在桌面显示”行为通过 WPF 配合 Windows 原生窗口 API 实现。
- RapidOCR 作为独立本地工作进程接入，由 WPF 调用并接收 OCR 结果，避免把 OCR 运行时绑定到界面进程。
- 当前已实现并验证 M1 时间、提醒和状态核心及 M2 本地识别、优先级和合成样本基线。M3 已有 WPF/WebView2 隐藏桥、本地 OCR 工作进程、真实 NapCat 只读接口及 Windows 探针代码和验证结果；通知探针已补齐自包含资源提取，受控冷启动回归及专用 URI 入口的用户实际点击通过，声音提醒已取消。本地 SQLite 收件箱、规则结果与正式事项生命周期已有实现和自动验证，AccountCandidateRouter 首轮本地候选自动路由、自动可靠关联变更与保守消息顺序协调已实现，ProcessAndRoutePending 在同一消息事务中提取及路由；正式应用骨架、基础页面及真实 QQ 到本地待确认的宿主已接入；正式桌面卡片首段已接入并验证；真实群课程确认后的任务验收、OCR 队列、桌面恢复/多屏及长期稳定性仍未完成，Windows 系统通知投递已取消。
- 首次启动显示简短引导，帮助完成初始连接、课程/群关联确认和桌面卡片预览；完成后登录 Windows 时在后台运行。
- 点击桌面卡片的“详情”或待确认事项，在主界面打开对应事项的原文、图片和变更记录。
- 事项较多时提供搜索和简单筛选，可按标题、课程、来源群或状态查找。
- 打开主界面时，若存在待确认事项则默认进入“待确认”页，否则进入“任务”页。
- 详情栏中的图片默认显示缩略图，点击后放大查看。
- OCR 文字默认折叠，用户点击“查看识别文字”后展开。
- OCR 识别出的图片日期以“建议日期”展示，只有用户确认后才正式用于提醒；用户可以修改或拒绝该建议。
