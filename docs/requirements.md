# 消息提纯：第一版已确认需求

更新日期：2026-10-11。本文记录已确认的产品需求，供后续界面设计和开发使用。

完整方案见 [Windows 第一版完整设计稿](superpowers/specs/2026-10-10-windows-app-design.md)。2026-10-10 用户选择 A，整体设计已确认；[实施总计划](superpowers/plans/2026-10-10-windows-app-implementation.md)和[第一阶段详细计划](superpowers/plans/2026-10-10-core-foundation.md)已写入。新版示例数据 demo 已完成浏览器验证，用户反馈 demo 基本满足要求。用户现明确授权完成准备后开始编写代码；M1 已完成，M2 本地规则与合成样本基线已完成并通过验证，M3 真实集成探针正在实施。Framework 已加载并自动登录，真实 OneBot 只读接口及实时群事件限定范围通过（观察到 1 条），用户确认聊天列表和窗口正常显示。Windows App SDK 通知发布资源已补齐，受控冷启动回调通过；用户实际通知点击、声音、桌面卡片人工操作、长期稳定性和完整历史补漏仍未验收；正式应用尚未接入这些探针能力。

## 1. 使用目标

- 面向 Windows 桌面，整理学校 QQ 群中的通知与作业，展示需要处理的事项。
- 消息分析、图片文字识别、存储和提醒在本机运行，第一版不接云端 AI。
- 参考“偷闲”的本地筛选、消息聚合及优先级架构，按学校场景调整规则。

## 2. QQ 消息接入

- 使用 NapCat，监听所有群聊；不处理私人对话和已确认机器人账号的消息。
- QQ 接入只读，不向 QQ 群或私聊发送消息。学校群通知、测试提醒和任务提醒均不通过 QQ 发送；任务提醒使用本机 Windows 通知。
- 用户已确认 QQ 在本机登录；接入时检查 NapCat 对应环境和连接是否就绪，普通 QQ 登录状态不作为 OneBot 连接成功的证明。
- NapCat 同时提供 Shell 和 Framework 两种接入模式。Shell 是无界面接管路线；同一账号不能同时登录普通桌面 QQ 和 Shell，不能把两个进程同时作为同一账号的接收端。Framework 在桌面 QQ 进程中加载 NapCat，目标是保留桌面聊天并提供消息接口；本机已加载并验证只读接口，用户确认聊天列表和窗口正常显示。实时群事件限定范围通过（观察到 1 条），长期稳定性尚未验证。
- 本机已准备并校验官方 NapCat Framework v4.18.37，在当前 QQ `9.9.36-53644` 中实际启动并自动登录；WebUI 6099 和 OneBot 3001 均已监听，只读探针取得 52 个群和一群一页的 7 条历史消息。原 QQ 文件未修改；不把这一页历史作为七天补漏通过，也未发送消息。
- 本地规则提出疑似机器人账号，用户确认后才排除；按账号记录，支持撤销。
- 首次启动尝试回溯最近 7 天的群消息；断线重连后自动尝试补漏。
- 界面显示 QQ 消息连接状态，连接断开时自动尝试恢复；每次持续断开超过 5 分钟后发一次系统通知，不在同一次断线期间反复提醒。恢复连接后重新计时，后续再次断开时按同样规则处理。
- 历史读取范围以 QQ 实际返回为准。补全失败时显示对应群和失败原因。
- 按群及消息 ID 去重，历史补漏不重复创建事项或重复触发相同提醒。
- 消息、证据、同步位置和提醒按 QQ 账号隔离，去重包含账号标识；切换账号须用户明确确认，同一时刻只有当前账号调度提醒，原账号数据保留。所有通知及汇总携带所属账号，切换协调在途发送并清理旧账号通知；延迟点击旧通知提示来源账号，只有显式切回后才查询和定位原事项。
- 登录 Windows 后自动启动软件，在系统托盘后台运行；自动启动默认开启，设置中提供开关，用户可自行关闭或重新开启。

## 3. 本地识别与相关性

- 只提取学校通知和作业，过滤日常闲聊。
- 结合行动要求、日期上下文、适用对象、群与课程关联等规则判断；短消息不能仅因字数少被丢弃。
- 自动提出课程及群关联候选，由用户确认、修改或排除，复用已确认关联，不要求先手填课程名单。
- 用户确认所提供 QQ 截图中红框标出的群均为学校相关群。学校群名称通常正规，群名可辅助提出关联候选；也存在非正式名称，不能仅凭群名风格排除。截图中截断的名称不补全，取得真实群列表后再核对。
- 保存课程/群关联修改后，重新检查受影响群仍保留的本地消息及已有事项证据，展示实际检查范围；找回原来被自动排除但现在可靠相关的事项，不承诺恢复已清理的消息。重查保留人工修正、确认/拒绝/忽略、合并拆分、完成/取消/归档及已发送记录，不因重查重放旧提醒；冲突或旧任务变得不相关时提出待确认建议，不自动删除任务，新发现临期事项按修复批次汇总。
- 自动识别面向全体及明确与本人课程相关的事项；相关性不确定时进入待确认。
- 必须完成的作业、考试、提交等事项可形成任务；自愿活动、竞赛等作为通知，用户可自行加入任务。
- 支持手动新增任务，用于补录口头布置或未被自动识别出的事项；用户填写标题、课程和截止日期/时刻，任务来源标注为“手动添加”，并使用与自动提取任务相同的优先级、提醒和完成规则。
- 根据消息原始发送时间解释“明天”“下周一”等相对日期，并区分提交期限、活动时间与其他日期。
- 需要行动但无法确定截止日期的事项进入待确认，补齐并确认后再安排截止提醒；已明确日期但没有具体时刻时，按仅有日期的提醒规则处理。

## 4. 图片辅助

- 图片文字识别采用 RapidOCR 本地方案，集成效果需通过实际学校群截图验证。
- 文字消息完整时，图片和 OCR 文字作为卡片的辅助信息。
- 文字消息缺少时间等关键信息时进入待确认，展示原图及 OCR 文字供用户手动补齐。
- 图片中的日期须经用户确认后才能用于提醒；OCR 失败时仍保留原图。
- demo 删除“我已查看原图并确认所填写的日期和时刻”的独立勾选框。用户填写或修改日期后，点击“确认并加入任务”或“保存修改”即完成确认；“填入建议”仅填入表单，提交前不确立正式时间。

## 5. 任务合并与变更

- 明确属于同一任务的内容、时间和补充要求合并，保留各条原始消息。
- 催交更新原任务；明确的延期、取消和要求修改按字段保护规则更新对应任务并记录变化；仍在待办中的任务同步更新卡片变化标记。
- 用户手动填写、纠正或确认图片建议的正式字段受保护，重复消息不覆盖。可信新延期与手动截止冲突时，保留旧正式值及当前提醒，显示待确认差异，用户接受后才替换和重算；未手动覆盖字段仍可自动更新。明确取消不受手动时间保护阻挡，确认课程/群关系不等于手动覆盖该群所有任务字段。
- 能明确关联到原任务的延期、取消或提交要求变更，除更新任务并记录变化外，额外发一次 Windows 系统通知说明变化；同一变更不重复通知。无法明确关联的变更仍进入待确认。
- 老师明确取消且能关联到原任务时，停止该任务后续提醒，移出待办和桌面卡片，保留“已取消”记录及原始消息；不记为用户已完成。取消变更仍按上述规则通知一次。
- 不能明确关联到某个任务的补充或变更消息进入待确认。
- 最近 7 天是消息回溯和分析窗口，不是任务保留期限；长期任务跨周保留。
- 逾期不自动完成或归档；任务由用户手动勾选完成，也可手动归档。
- 任务详情提供“归档”，归档后移出待办和桌面卡片、停止后续时间提醒并清理旧通知，保留“已归档”记录及证据，不记为已完成。任务页提供已归档筛选，详情可手动恢复待办；恢复使用最新有效信息，不重发已发送节点。
- 已归档事项不因重启、重查或普通补充自动恢复；收到明确新行动要求时形成关联待确认建议，用户接受后再恢复待办。
- 完成后移入已完成记录，停止提醒，保留原始消息供查看。
- 已完成任务收到能明确关联的新行动要求时，自动恢复为待办，标出新要求，并按提醒规则继续提醒；保留之前的完成记录及新旧消息证据。普通补充说明不自动恢复；关联或有效截止信息无法确定时，仍按既有规则进入待确认。
- 点击“完成”后立即移入已完成记录，并提供 1 小时内的撤销入口；撤销后恢复为未完成状态并继续按规则提醒。
- 完成后的即时提示和 1 小时内的已完成记录均使用“撤销”作为撤销按钮文字。
- 忽略待确认事项后提供 1 天内的“撤销”入口；撤销后恢复到待确认列表。
- 新任务、通知和待确认事项显示未读数量及小红点。
- 打开并查看新任务、通知或待确认事项后自动标记为已读。
- 点击主窗口关闭按钮时默认隐藏到系统托盘并继续运行；设置中允许改为直接退出软件。

## 6. 优先级与提醒

- 本地自动计算 P0～P3，用户可以手动调整；结合截止时间与明确的事项后果。
- 基础分级：P0 为已逾期或今天截止；P1 为未来 3 天内；P2 为未来 7 天内；P3 为更晚。依次匹配，避免区间重叠。
- 明确影响成绩、考试资格或说明逾期不收时，可提高一级；不根据孤立关键词推断后果。
- 实时新发现或手动新增、有效时间尚未过去的 P0/P1 任务通过卡片高亮和 Windows 通知提醒；历史导入、补漏及关联修复按批次汇总。历史首次发现时已经逾期的任务只保留卡片高亮，不触发新任务系统通知。
- 作业、考试和需要提交的任务的 Windows 提醒播放系统声音；普通通知及不需要完成的事项保持静音。
- 作业、考试和提交类任务在每个正常提醒节点请求一次系统声音；多个节点合成一次通知或汇总时最多请求一次，实际声音受 Windows 设置影响。
- 设置中提供“任务声音提醒”总开关；关闭后仍保留视觉通知和桌面卡片提醒。
- 设置中保留“安静时段”入口，Windows 第一版标注为“暂未启用”，暂不实现按时段自动静音；具体时间和行为留待未来若规划手机版时再讨论。手机版开发尚未确定。
- 提醒按已确认时间类型及精度安排：提交任务以截止为基准，考试/需参加活动以开始为基准。明确具体时刻时提前 1 天（24 小时）和 2 小时各提醒一次；仅明确某一天时，在该日期前一天中午 12:00 提醒。开始时间已过显示对应标签，不误记为作业逾期或自动完成；只有日期时当天仍有效。
- 任务详情中允许单独调整该任务的提醒时间；未设置自定义提醒的任务继续使用上述默认规则。自定义提醒时间与截止时间分别保存，不改变正式截止时间或其精度。
- 有效延期按字段保护规则接受后，时间精度兼容的自定义提醒随新正式时间调整，保持原来的提前间隔；未自定义的任务按新时间重算默认节点，旧安排失效。与手动正式字段冲突且尚未接受的建议不使原提醒失效。
- 自定义支持提前若干小时、前若干天的某时刻及关闭该任务时间提醒。仅日期信息不能建立小时倒推的虚构正式时刻；明确时刻时不把截止/开始后的时刻设为提前提醒。
- 新正式时间仅有日期、导致原小时自定义规则失效时，临时采用对应默认提醒，明确显示“原自定义提醒不再适用，当前使用默认提醒”，并提供关联的提醒设置待确认项；用户可重设或关闭。前若干天某时刻的日历规则保持原偏移及钟点；用户已关闭的时间提醒不因延期或精度变化重新打开。
- 仅有日期时保留日期信息，不凭空补写具体截止时刻。上述安排替代原先统一提前 3 天、提前 1 天和截止当天的提醒方案。
- 电脑关机、睡眠或软件未运行导致错过截止前提醒时，恢复运行后对尚未截止且仍待处理的任务补发一次汇总提醒；同一任务错过多个节点时合并，不重复补发已经处理过的提醒。已逾期任务不补发系统提醒，只保留卡片高亮。
- 逾期后仅保留卡片高亮，不重复弹出 Windows 通知；任务保持待处理，直到用户手动完成或归档。
- 待确认事项不使用每日定时汇总通知，通过常驻桌面卡片提示用户处理。
- 首次历史导入、断线补漏各使用持久化批次，处理结果逐步展示，结束后只发一次符合条件的汇总，同一事项的发现、变更及错过节点合并。已结束批次后的迟到旧消息进入新的持久化小批次，首个符合汇总条件的结果入批后 5 秒内自动关闭；有效时间不足 5 秒时立即提交，不等待下次断线，不重报实时已通知内容。
- 同一账号/事项的状态变更与 Windows 通知提交串行协调，覆盖在途提交：取消、完成、归档或延期先完成时不再提交旧时间节点，旧提交先发生时后续变更清理其条目；汇总同时校验成员版本，失效成员不混入旧时间汇总。有效取消变更通知仍保留一次，旧账号通知按账号隔离和清理。

## 7. 桌面卡片与通知列表

- 桌面组件统一展示“提醒事项”和“待确认”两张卡片，可拖动、调整大小，固定在桌面显示。
- 两张桌面卡片采用左右排列。
- 桌面卡片仅在桌面显示，切回桌面时可见，不覆盖其他软件窗口。
- 两张桌面卡片首次显示时由软件根据屏幕空间自动摆放；用户拖动或调整大小后记住新的位置和尺寸。
- 提醒事项卡片按优先级和截止时间排序，显示任务标题、课程或来源群、优先级、截止时间及查看详情、完成入口。
- 临近截止和逾期任务高亮；任务保留到手动完成或归档，明确取消的任务按取消规则移出，没有任务时显示“暂无待办”。
- 待确认卡片在存在待确认事项时常驻，不自动消失；显示标题、来源和待补信息，可查看原文与图片。
- 补齐并确认的事项转入正式任务或通知；无关或误报事项可忽略。处理一项减少一项，全部处理完后隐藏待确认卡片。
- 已识别清楚且无需完成任务的普通通知，仅放在软件主界面的通知列表中，不增加桌面通知卡片。
- 主界面采用左侧导航，包含“任务、待确认、通知、已完成、设置”；右侧显示所选页面的内容。
- 点击事项后在主界面右侧详情栏查看原文、图片，并修改截止时间等信息；保留事项列表，方便连续处理。
- 详情内容超过窗口高度时，右侧栏独立支持鼠标滚轮滚动。待确认表单底部固定显示确认操作及去向说明：选择“任务”并补齐必要信息后“确认并加入任务”；选择“通知”则“确认并保留为通知”。信息不完整时显示可见的错误提示。
- 列表课程筛选与详情／新增表单的“课程或分类”共用同一份下拉选项，包含已有课程、分类和用户自定义名称。支持从下拉框新增自定义课程或分类，保存后各处立即同步，刷新后保留；更新选项不丢失表单中尚未提交的内容。筛选选择与事项所属课程分别保存，不因编辑课程而自动改变筛选条件。
- 支持自由切换浅色模式和深色模式，深色模式使用纯黑背景，主界面与桌面卡片使用统一主题；切换时有柔和的过渡动画。
- 首次打开时默认跟随 Windows 系统主题，用户之后可在设置中自由切换。
- 按钮点击有轻微的按压过渡；任务卡片、桌面卡片及卡片内条目悬停时有短距离位移和阴影反馈，并支持减少动画设置。

## 8. 实现技术路线

- 真实 Windows 应用采用 **C# WPF + WebView2**。
- 现有 HTML/CSS/JS 原型作为 WebView2 中的界面基础继续复用；WPF 负责窗口生命周期、系统托盘、登录后启动、Windows 通知、本地持久化、NapCat 通信、提醒调度及桌面卡片窗口层级。
- 桌面卡片的“仅在桌面显示”行为通过 WPF 配合 Windows 原生窗口 API 实现。
- RapidOCR 作为独立本地工作进程接入，由 WPF 调用并接收 OCR 结果，避免把 OCR 运行时绑定到界面进程。
- 当前已实现并验证 M1 时间、提醒和状态核心及 M2 本地识别、优先级和合成样本基线。M3 已有 WPF/WebView2 隐藏桥、本地 OCR 工作进程、真实 NapCat 只读接口及 Windows 探针代码和验证结果；通知探针已补齐自包含资源提取并通过受控冷启动回归，但用户实际通知点击/声音仍待验收。正式应用骨架、SQLite、端到端消息处理、正式通知投递和桌面驻留仍未完成。
- 首次启动显示简短引导，帮助完成初始连接、课程/群关联确认和提醒预览；完成后登录 Windows 时在后台运行。
- 点击 Windows 提醒后直接打开对应事项的详情页面。
- 事项较多时提供搜索和简单筛选，可按标题、课程、来源群或状态查找。
- 打开主界面时，若存在待确认事项则默认进入“待确认”页，否则进入“任务”页。
- 详情栏中的图片默认显示缩略图，点击后放大查看。
- OCR 文字默认折叠，用户点击“查看识别文字”后展开。
- OCR 识别出的图片日期以“建议日期”展示，只有用户确认后才正式用于提醒；用户可以修改或拒绝该建议。
