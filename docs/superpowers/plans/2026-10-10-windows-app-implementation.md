# 消息提纯：Windows 第一版实施总计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement each milestone. Steps use checkbox (`- [ ]`) syntax for tracking. 用户的小任务快速通道优先；小任务省略重流程，每次改动仍必须更新测试、全部验证通过并提交 Git commit。

**Goal:** 将已确认的浏览器原型变成在本机整理 QQ 学校群消息、保存事项并提供桌面卡片与 Windows 提醒的真实应用。

**Architecture:** WPF 管理生命周期和 Windows 集成，WebView2 复用现有视觉；纯 C# 核心负责时间、规则和状态决定。SQLite 是正式数据来源，NapCat 接收消息，独立 RapidOCR 进程处理图片，通知由同一持久化调度入口提交。

**Tech Stack:** .NET 10 LTS、C#、WPF、WebView2、SQLite、Windows App SDK、OneBot 正向 WebSocket、Python/RapidOCR CPU 模型；Windows x64。

**Spec:** [已确认设计](../specs/2026-10-10-windows-app-design.md)、[有效需求](../../requirements.md)、[项目交接](../../HANDOFF.md)。

## Global Constraints

- 2026-10-10 用户选择 A，整体设计已确认；随后确认 demo 先行。新版 demo 已完成浏览器验证，用户反馈基本满足要求，确认 QQ 已在电脑登录并授权完成准备后开始编写代码。M1、M2 已完成，M3～M9 尚未执行；demo 使用示例数据，不替代真实环境验证。
- Windows x64，采用 .NET 10 LTS；先验收本机 Windows 11，其他系统须另测。
- 不接云端 AI，不上传消息，不增加手机版、云同步或在线自动更新。
- NapCat 与 RapidOCR 路线沿用已确认选择；课程/群候选由系统提出，用户确认，不改为首次手填名单。
- 全群监听，排除私聊及经用户确认的机器人；回溯最近 7 天是尽力尝试，不是任务寿命。
- 日期精度不制造正式时刻；默认精确提醒提前 24 小时、2 小时，日期提醒为前一天 12:00。
- 完成撤销 1 小时，忽略撤销 24 小时，撤销文字为“撤销”；期限和后续替代关系持久化。
- 逾期不自动完成或归档；已完成与已归档收到新要求按各自已确认规则处理。
- 手动正式字段与新建议分开；未接受冲突不使旧正式提醒失效，OCR 日期须用户确认。
- 深色背景纯黑；主题过渡 320ms；按压及悬停动画尊重减少动画偏好。
- 桌面两卡片左右排列，只在桌面显示；置顶窗口不能作为桌面宿主验收结果。
- 声音按事项及总开关处理；安静时段只保留“暂未启用”入口。
- 每次改动更新相关测试；所有测试和验证通过后创建对应 Git commit，同时更新交接。
- 真实 QQ、OCR、桌面宿主、安装通知激活及一周使用观察均须记录实测；不能用模拟测试代替。
- M3 探针当前结果：Infrastructure 46/46、Windows 44/44、OCR 25/25、Node 15/15，WebView2 隐藏桥已实测通过；真实 QQ 3001 未就绪，非提权通知和桌面人工项未完成。详见[集成探针验证记录](../../verification/integration-probes.md)。

## 2. 文件与组件边界

下列是各阶段的组件路径。当前 Core、Core.Tests、合成 fixtures 和规则基线 CLI 已存在，其他基础设施及 Windows 宿主尚未实现；最新进度见交接文档。

| 路径 | 职责 |
| --- | --- |
| `src/MessagePurify.Core/` | 时间精度、优先级、提醒计划、状态转换、本地提取与关联规则；不访问窗口、网络或数据库 |
| `src/MessagePurify.Infrastructure/Storage/` | 按账号的 SQLite 事务、迁移、证据文件、建议与处理记录 |
| `src/MessagePurify.Infrastructure/NapCat/` | WebSocket 请求响应、账号/依赖状态、实时接收、历史分页和批次 |
| `src/MessagePurify.Infrastructure/Ocr/` | 隐藏工作进程、JSON Lines、队列、超时及结果持久化 |
| `src/MessagePurify.Infrastructure/Notifications/` | 持久化投递记录、账号/事项串行协调、汇总及恢复处理 |
| `src/MessagePurify.Windows/` | WPF 主进程、WebView2 桥、单实例、托盘、桌面宿主、启动项及通知适配器 |
| `src/MessagePurify.Windows/ui/` | 从原型复用的发布界面，移除示例数据、重置示例和浏览器桌面模拟 |
| `ocr/worker.py` | RapidOCR CPU 推理，标准输入/输出只使用一行一个 JSON，日志走标准错误 |
| `tests/MessagePurify.Core.Tests/` | 可控时间下的纯规则、时间与状态测试 |
| `tests/MessagePurify.Infrastructure.Tests/` | 临时数据库、模拟 OneBot、假通知端、假 OCR 进程和故障恢复测试 |
| `tests/MessagePurify.Windows.Tests/` | 桥参数校验、单实例请求、通知账号路由及可自动检查的 Windows 行为 |
| `tests/fixtures/` | 合成回归样本；真实群样本脱敏并保存在用户本机，不提交凭据和私人正文 |
| `docs/verification/` | 实际运行环境、命令、结果、未测试项和失败边界 |
| `packaging/` | 当前用户固定路径安装、依赖检测、离线 OCR 文件及许可清单 |

`Core` 不引用 `Infrastructure` 或 `Windows`；`Infrastructure` 引用 `Core`；`Windows` 组合两者。正式事项 ID、QQ/群/消息 ID 在前端均传字符串。持久化接口在进入 M4 时由该阶段详细计划定义，不在本轮猜测整套数据库方法。

## 5. 每次提交的验证顺序

先运行受影响模块测试，再运行全部已有测试；未创建的项目不算当前通过项。随阶段加入 .NET、OCR 和安装检查，更新 `tests/README.md`，不要永远只跑原型检查。

当前实际可执行：

```powershell
node --test tests/project-rules.test.mjs
node tests/prototype-qa.mjs
git diff --check
```

M1 建立核心后加入：

```powershell
dotnet test tests/MessagePurify.Core.Tests --no-restore
```

M3 起对所有已建项目执行 `dotnet build`、各测试项目 `dotnet test`；首次锁定并记录实际通过的 NuGet、SDK、NapCat/QQ、OCR/模型版本。依赖锁文件提交到 Git，后续恢复使用锁定版本。安装与真实 Windows 验收单独记录，不能用 build 替代。

每次验证后同步 `docs/HANDOFF.md`，检查待提交文件、`git diff --check`、`git diff --cached --check`，只暂存本次范围再提交；用 `git log -1` 和 `git status --short` 确认提交与剩余改动。若只有文档变化，更新对应文档检查并运行全部现有测试。
