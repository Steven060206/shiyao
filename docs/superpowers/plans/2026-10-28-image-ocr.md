# 图片下载、本地 OCR 与原图备份实施计划

**Goal:** 用户已授权继续，将现有离线 worker 接入真实消息、原图详情及可恢复备份。

**Spec:** `docs/requirements.md` 第4/9节，以及 `docs/superpowers/specs/2026-10-10-windows-app-design.md` 第8节。沿用已确认的本机、RapidOCR、图片日期建议和QQ只读决定，无需重选方案。

**Architecture:** 原消息保持不变，账号 messages.sqlite3 增加图片状态表，原图按内容哈希保存在账号 images 目录。同步期间调用 NapCat `get_image`，复制返回的本地文件；QQ恢复后离线进程顺序识别。OCR结果只增强证据/建议，无业务记录的遗漏可产生待确认；已有任务和人工处理受保护。界面通过同源受控证据URL显示图片，备份携带原图及哈希并兼容旧包。

## 约束

- 不向QQ群或私聊发消息，不使用QQ服务端OCR，不上传原图。
- 图片时间不直接成为正式时间；用户提交确认后才生效，原图失败可手动补齐。
- 不更改既有app.css/index.html/application-ui.test.mjs视觉dirty，发布仅用干净已提交源码。
- 每项补真实有意义回归，验证后Git commit；软件更新推main及新Release并保留本机数据。
- 游戏/停止/恢复取消异步工作，应用结果前核对账号、代数与图片当前状态。
