## 1. 改版目标与范围

把“拾要”统一为温润、安静、适合长期阅读与处理消息的个人助理界面。浅色以米白、墨绿、少量暖金形成层次；深色以接近黑色的基底、暖黑面板和深墨绿选中背景形成层次。

“安静”的验收含义是：信息层级清楚、装饰克制、重要任务容易发现、主要操作容易识别。不能通过降低正文对比度、隐藏操作、缩小文字或淡化截止提醒来实现。

保留 WPF + WebView2、现有数据模型、桥协议、消息状态和 DesktopCardHost。只调整视觉、必要的展示结构与样式资源组织。

### 1.1 必须保留

- 任务、待确认、通知、已完成、回收站、设置六个入口及各自操作。
- 搜索、课程筛选、既有时间倒序规则、批量审核、撤销、设置表单和原文证据。
- 现有按钮对应的命令、可用条件、确认流程与反馈；不借视觉改版重定义状态流转。
- SQLite schema、消息同步、备份格式和 QQ 只读边界。
- 桌面卡片半透明、16 DIP 圆角、拖动、缩放、吸附、滚动、位置尺寸记忆、完成和查看详情。
- 无待办隐藏、新待办恢复、隐藏卡片不参与吸附等现有规则。
- 已有主题偏好、窗口约束、数据目录与配置格式。

### 1.2 实现边界

- 不新增图标库、在线字体或外部样式依赖；复用 `assets/shiyao.png`、`shiyao.ico`、现有图标与系统字体。
- 允许为主题映射增加小型资源文件及必要的资源打包声明，不引入新的主题框架或桥命令。
- 不把视觉改版扩展为数据重构、消息算法调整或业务功能开发。
- 修改前检查仓库 `AGENTS.md`、实际文件路径和未提交改动，保护其他工作。
- 本文参数为建议设计基线，不代表已查看或验证仓库现状。项目已有明确确认的参数优先；冲突在 Task 0 中说明并收敛。

## 2. 视觉基线

### 2.1 颜色与语义 Token

采用以下默认配色制作预览。最终颜色在设计确认后固定，两个主题分别验证对比度。

| Token | 浅色建议值 | 深色建议值 | 用途 |
| --- | --- | --- | --- |
| `--paper` | `#F5F3EC` | `#0C0F0D` | 页面基底 |
| `--paper-raised` | `#FFFEFA` | `#171D19` | 内容面板、详情与弹层 |
| `--ink` | `#25332D` | `#EAECE3` | 主文字 |
| `--muted` | `#5F6B63` | `#A7B0A4` | 来源、时间等辅助文字 |
| `--moss` | `#315B46` | `#A5C8AC` | 品牌强调、主按钮、选中标记 |
| `--on-accent` | `#FFFEFA` | `#14281B` | 主按钮内文字 |
| `--accent-hover` | `#274A39` | `#B6D5BA` | 主按钮悬停背景 |
| `--accent-active` | `#1F3D2E` | `#93B89A` | 主按钮按下背景 |
| `--brass` | `#7B5E2C` | `#D1B775` | 少量暖金强调 |
| `--line-soft` | `#DBDED5` | `#2E3931` | 装饰性分隔线 |
| `--border-control` | `#788578` | `#718575` | 需要可识别边界的输入控件 |
| `--selected-bg` | `#E6EDE3` | `#24382B` | 列表选中背景 |
| `--danger` | `#AB3838` | `#EF9990` | 现有危险操作、错误或逾期提示 |
| `--warning` | `#815A14` | `#E0BC74` | 现有警告或待确认提示 |
| `--focus-ring` | `#315B46` | `#A5C8AC` | 键盘焦点标记 |

使用规则：

- 品牌强调色与状态语义分开；暖金不承担所有状态的提示职责。
- `--line-soft` 只作轻分隔，不作为输入框或关键状态唯一的可见边界。
- 状态采用现有文字，并可配合现有图标；不只靠红、绿、金区分。
- 普通有效文字对比度至少 4.5:1；识别控件或状态所必需的非文字视觉信息至少 3:1。禁用态和纯装饰按适用范围处理。
- 检查实际前景、背景与透明度组合；半透明卡片不能只检查未叠加壁纸的颜色值。
- 以上建议值需要覆盖实际组件组合，并不等于所有透明度、渐变和状态搭配已经合格。

### 2.2 字体、尺寸与空间

以下尺寸用于 Web 界面的预览基线，单位为 CSS px。WPF 使用 DIP，并通过实际渲染核对视觉一致性，不把 CSS 尺寸当成物理像素直接复制。

| 项目 | 建议基线 | 约束 |
| --- | --- | --- |
| 字体 | 现有系统字体栈；中文优先可用的 Microsoft YaHei UI | 不下载字体，不更换为装饰字体 |
| 正文与列表标题 | 14 px，行高约 1.5 | 不通过缩小文字增加容量 |
| 页面标题 | 20 px，适度加粗 | 不重复展示大号品牌和页面标题 |
| 区域标题 | 16 px | 与正文形成清晰层级 |
| 时间等辅助文字 | 12–13 px | 保持可读对比度 |
| 间距尺度 | 4 / 8 / 12 / 16 / 24 px | 避免各区域自行设定零散间距 |
| 侧栏宽度 | 208 px | 在实际最小窗口下验证 |
| 列表栏宽度 | 默认 360 px | 沿用现有分栏与窗口适配策略 |
| 内容留白 | 默认 24 px，较窄窗口 16 px | 操作和正文不能被挤出可见区域 |
| 列表行 | 默认最小高度 68 px | 内容必要时增高；长标题最多两行，详情显示完整标题 |
| 普通操作按钮 | 建议高度至少 32 px | 复用现有交互目标；桌面卡片单独验证 |
| 圆角 | 普通控件 8 px，面板 12 px | 桌面卡片保留现有 16 DIP |

不为了套用建议尺寸修改已保存的窗口尺寸或位置。最小窗口下若基线无法容纳内容，在预览中确定兼容布局，不能靠隐藏入口或横向裁切解决。

## 3. 信息与操作布局

### 3.1 导航分组

| 分组标记 | 入口 |
| --- | --- |
| 处理 | 任务、待确认、通知 |
| 记录 | 已完成、回收站 |
| 偏好 | 设置 |

分组只是视觉标记，不增加页面、路由或命令。入口名称、图标语义、数量来源与点击行为沿用现有实现。

### 3.2 工具与动作位置

| 区域 | 显示内容 | 行为要求 |
| --- | --- | --- |
| 页面顶部 | 当前页面标题、同步状态、同步动作 | 保留原同步反馈和错误说明；弱化重复面包屑 |
| 列表工具栏 | 搜索、课程筛选、现有排序控件 | 保留各页面原本支持的能力与查询条件 |
| 列表选择状态 | 批量选择数量、现有批量审核等动作 | 仅在原有适用页面和条件下显示，不能被简化顶部时删除 |
| 详情动作区 | 当前条目的现有主要和次要动作 | 完成、审核等按原状态提供；破坏性动作保持既有确认流程 |
| 原撤销反馈位置 | 现有撤销入口和提示 | 保留时间窗口、可见时机与行为 |
| 设置页 | 原有全部设置项、保存和反馈 | 不隐藏、重命名或改变持久化语义 |

### 3.3 列表信息层级

- 第一层：标题；临近截止、逾期或待确认等现有重要提示紧邻标题或放在同一可见区域。
- 第二层：课程、来源等信息，用普通文字与间距组织。
- 第三层：最新消息时间、普通元数据，以及未在第一层强调的截止信息。
- 没有截止信息的通知等条目，不补造时间或显示空标签。
- 重要提示的判定复用现有业务规则，不在视觉层重新定义“临近截止”和“逾期”。
- 选中行使用背景和侧边标记；悬停、选中与键盘焦点需要能够区分。
- 现有排序保持不变；此处调整的是信息强调程度。

### 3.4 详情阅读顺序

标题 → 来源与时间 → 主要动作 → 现有正式字段 → 原文证据。

原文使用引用块视觉。原文文字、链接、复制能力、滚动与已有展开行为保持原样；长链接和长连续文本需要安全换行，不能导致整页溢出。详情的重新排布不能覆盖或重置当前编辑内容。

## 4. 交互与主题一致性

### 4.1 组件状态

| 状态 | 必须表达的效果 |
| --- | --- |
| 默认 | 有效按钮可识别；主动作比普通动作明显 |
| 悬停 | 背景或边界有明确变化；不改变布局尺寸 |
| 按下 | 有即时反馈；不产生按钮跳动 |
| 键盘焦点 | 清楚可见，不被容器裁切；焦点顺序与阅读顺序合理 |
| 选中 | 列表当前条目明确；不与悬停效果混淆 |
| 禁用 | 可辨认且不可触发；沿用既有禁用条件 |
| 加载 | 沿用现有加载反馈与重复点击保护，不另造业务状态 |
| 错误 | 原有错误说明与恢复入口可见，不仅改变颜色 |

仅对颜色、透明度等轻量属性使用约 120–180 ms 过渡。不要使用持续呼吸、弹跳、闪烁或整块内容位移。支持减少动态效果的环境中减少或取消非必要过渡。关键操作不能仅在鼠标悬停时才可发现。

### 4.2 Web 与 WPF 配色

- Task 0 先确认桌面卡片的实际主题来源：跟随应用、跟随系统或已有独立偏好；保留既有逻辑。
- CSS 变量与 WPF 颜色/Brush 使用同一份已确认的语义配色规范。可采用小型共享主题清单，或显式映射表配合自动比对。
- 如果采用共享文件，明确 CSS 和 C# 两端如何读取、生成或映射，确保资源随发布包提供；不为此修改现有桥协议。
- 不允许仅在 `app.css` 定义变量，而在 `DesktopCardHost.cs` 再维护一套无校验的颜色值。
- 同一语义在相同主题下保持一致；半透明背景的最终像素可能不同，需要单独验证可读性。
- 切换主题时按现有通知机制刷新相关界面；当前选择、筛选、原文、编辑内容与卡片位置不能被重置。
