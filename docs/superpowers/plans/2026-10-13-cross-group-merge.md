# 跨群可能重复建议实施计划

**目标：** 为已确认同课程的不同群中的严格重复通知提供人工合并建议，复用已有合并差异和保持独立操作。

**依据：** `docs/requirements.md` 第 5 节与已确认 Windows 设计第 7.2 节。当前基线 `a16ccea`，沿用 `codex/m3-integration-probes` 分支；用户已授权继续开发，无需再次选择执行模式。

**实现方式：** 建议由工作区快照派生，不伪造普通待确认候选，不新增数据库迁移。建议携带双方 ID/版本，实际写入继续使用既有双版本事务。原文及原候选严格匹配，只规范化 NFKC 与空白；当前手动修改的正式值保留并在差异界面核对。

## 约束

- QQ/NapCat 只读，不得发送群聊或私聊消息；仅使用隔离合成数据进行本轮 Native 验证。
- 不放宽跨群延期、取消等自动关联规则，不自动合并；同课程关系不能证明同一班级或对象。
- 排除来源缺失、多行动、共享证据、含引用且上下文无法核实的来源、合并来源及拆分家族；尊重双方及合并别名的保持独立决定。
- 不切换默认入口及正在运行正式版本；OCR、额外安全增强和统一真实验收后置。
- .NET 构建及全量验证串行运行，代理按文件所有权分工。
