# 项目检查

在项目根目录运行全部现有测试：

```powershell
node --test tests/project-rules.test.mjs
node tests/prototype-qa.mjs
```

第一条包含 8 项检查：协作规则同步、小任务规则优先级、交付文件和文档链接、整体设计状态、全部设计验收场景的计划覆盖，以及新版演示的保存方式和真实集成边界。

第二条包含 102 项浏览器检查，覆盖原有主题／动画、排序、桌面卡片、图片确认及通知转任务，并新增：首次引导、已读行为、完成 1 小时／忽略 24 小时撤销及刷新、归档恢复、搜索与筛选、手动任务与开始时间、自定义提醒、延期及精度失效、人工字段冲突、新行动要求、取消、图片放大及 OCR 折叠、通知内容／声音意图预览、设置与桌面布局保存。详情栏的回归检查在 1100×800 窗口中确认长内容不被裁切，使用 Chrome 原生鼠标滚轮上下滚动及原生点击固定确认按钮，核对任务／通知的去向和错误提示可见性。课程相关新增 16 项检查，覆盖共享选项、两处自定义入口、刷新和重置、重复／空白名称、取消恢复选择、未提交表单保留、待确认／手动任务使用自定义课程及筛选。测试在截止边界显式验证撤销资格，并通过过期动作检查防止越界恢复；未实际等待 1 小时或 24 小时。动画与系统主题测试显式模拟媒体偏好，不依赖本机 Windows 设置。

真实应用尚未创建 .NET 或 OCR 测试项目。实施时按 [总计划](../docs/superpowers/plans/2026-10-10-windows-app-implementation.md) 将新增测试命令补入本文；计划中的 C# 示例和验收目标不计为本轮已运行测试。

需要 Node.js 22 或更新版本和 Chrome。默认使用 `C:/Program Files/Google/Chrome/Application/chrome.exe`；其他安装位置可通过环境变量 `CHROME_PATH` 指定。浏览器检查使用独立临时配置，不访问个人浏览器会话。普通测试不会覆盖预览图；仅在主动更新预览时运行 `node tests/prototype-qa.mjs --screenshots`，生成课程选择、待确认、主界面及桌面卡片的六张预览。

这些检查验证文档和浏览器原型，不代表真实 QQ、OCR、Windows 系统通知或桌面驻留已通过测试。
